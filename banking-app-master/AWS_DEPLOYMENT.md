# AWS_DEPLOYMENT.md — Deploying the RCA Platform to AWS

This guide walks through deploying the full banking-app RCA pipeline to AWS ECS Fargate using the Terraform configuration in `terraform/aws/`.

**Architecture:** VPC → public subnets → ECS EC2 container instance + EC2 tasks → RDS MySQL. Credentials stored in SSM Parameter Store (free tier). No CI/CD pipeline — images are built and pushed manually.

**Services deployed:**
- `banking-app` — Spring Boot (H2 in-memory) + Datadog agent sidecar, on public port 8080
- `ingestion-agent` — Python, MODE=datadog_poll (polls Datadog Logs API → RDS)
- `rca-agent` — Python FastAPI + poll loop (RCA_POLL_ENABLED=true), on public port 8000

---

## Prerequisites

- AWS CLI configured (`aws configure`) with permissions for ECS, ECR, RDS, VPC, IAM, SSM
- Terraform >= 1.6
- Docker (for building and pushing images)
- Real Datadog credentials (DD_API_KEY, DD_APP_KEY)
- Anthropic API key, GitHub PAT, Google Gemini API key

## Step 1 — Terraform Init & Apply

```bash
cd terraform/aws

# Create your tfvars file
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars — fill in aws_region, environment, github_org, dd_site

terraform init
terraform plan -var-file=terraform.tfvars
terraform apply -var-file=terraform.tfvars
```

This creates (in order):
1. VPC, public subnets, security groups
2. RDS MySQL instance (takes ~5 minutes) — **password auto-generated by Terraform**
3. ECR repositories (4 repos)
4. SSM Parameter Store parameters:
   - `rds-password` and `database-url` — **auto-populated by Terraform** (no manual step)
   - `anthropic-api-key`, `github-pat`, `gemini-api-key`, `dd-api-key`, `dd-app-key` — placeholder values, overwrite in Step 2
5. ECS cluster, task definitions, and services

Note the outputs — you'll need them in the next steps:
```bash
terraform output ecs_cluster_name
terraform output rds_endpoint            # for reference / direct DB access
terraform output ecr_banking_app_uri     # for docker push commands
terraform output ssm_parameter_names     # shows all parameter paths
```

## Step 2 — Populate SSM Parameter Store

After apply, five external-service credentials need to be set. The database password and full `DATABASE_URL` are **auto-populated by Terraform** — you do not need to set those manually.

SSM Parameter Store standard parameters are **free** — no per-secret monthly charge unlike Secrets Manager. Values are encrypted at rest using the AWS-managed KMS key (`aws/ssm`) and injected into ECS containers at task start — never stored in images or task-definition plaintext.

```bash
# Helper function
function put_param() {
  aws ssm put-parameter \
    --name "$1" \
    --value "$2" \
    --type SecureString \
    --overwrite
}

put_param "/banking-app/production/anthropic-api-key" "sk-ant-..."
put_param "/banking-app/production/github-pat"         "ghp_..."
put_param "/banking-app/production/gemini-api-key"     "AIza..."
put_param "/banking-app/production/dd-api-key"         "<your-dd-api-key>"
put_param "/banking-app/production/dd-app-key"         "<your-dd-app-key>"
# rds-password and database-url are managed by Terraform — do NOT overwrite them.
```

> **Verify all parameters are set:**
> ```bash
> aws ssm get-parameters-by-path \
>   --path "/banking-app/production" \
>   --with-decryption \
>   --query "Parameters[*].{Name:Name,Value:Value}" \
>   --output table
> ```
> The `rds-password` and `database-url` rows should already have real values from Terraform.
> The other five rows should show the credentials you just set (not `REPLACE_ME`).

## Step 3 — Build and Push Images to ECR

```bash
# Authenticate Docker with ECR
AWS_ACCOUNT=$(aws sts get-caller-identity --query Account --output text)
AWS_REGION=us-east-1
ECR_BASE="${AWS_ACCOUNT}.dkr.ecr.${AWS_REGION}.amazonaws.com"

aws ecr get-login-password --region ${AWS_REGION} \
  | docker login --username AWS --password-stdin ${ECR_BASE}

# From the banking-app-master root:
cd banking-app-master

# 1. banking-app (Spring Boot + Java)
docker build -t banking-app .
docker tag banking-app:latest ${ECR_BASE}/banking-app:latest
docker push ${ECR_BASE}/banking-app:latest

# 2. error-ingestion-agent (context = repo root so projects.yaml can be baked in)
docker build -f error-ingestion-agent/Dockerfile -t ingestion-agent .
docker tag ingestion-agent:latest ${ECR_BASE}/banking-app/ingestion-agent:latest
docker push ${ECR_BASE}/banking-app/ingestion-agent:latest

# 3. rca-agent
docker build -t rca-agent ./rca-agent
docker tag rca-agent:latest ${ECR_BASE}/banking-app/rca-agent:latest
docker push ${ECR_BASE}/banking-app/rca-agent:latest

# 4. Datadog agent sidecar (custom image with banking-app log config baked in)
docker build -t dd-agent ./datadog
docker tag dd-agent:latest ${ECR_BASE}/banking-app/dd-agent:latest
docker push ${ECR_BASE}/banking-app/dd-agent:latest
```

> **Note:** After every code change, rebuild the affected image and push to ECR, then force a new ECS deployment:
> ```bash
> aws ecs update-service --cluster banking-app-cluster \
>   --service <service-name> --force-new-deployment
> ```

## Step 4 — Run Alembic Migrations

The `rca-agent` Dockerfile already runs `alembic upgrade head` in its CMD. On first deploy, ECS will run migrations automatically when the task starts.

If you need to run migrations manually (e.g., after a schema change):

```bash
# Connect to the rca-agent task via ECS Exec
aws ecs execute-command \
  --cluster banking-app-cluster \
  --task <task-id> \
  --container rca-agent \
  --interactive \
  --command "alembic upgrade head"
```

## Step 5 — Seed service_repo_map

The RCA agent needs to know which GitHub repo to search for each service. Run the seed script once after initial deploy:

```bash
# Pull the full DATABASE_URL from SSM (Terraform stored it there — password included)
DB_URL=$(aws ssm get-parameter \
  --name "/banking-app/production/database-url" \
  --with-decryption \
  --query "Parameter.Value" \
  --output text)

python demo-repos/demo_seed_data.py \
  --org oscorpAI \
  --db-url "${DB_URL}"
```

This inserts `banking-app`, `payment-service`, and `order-service` into `service_repo_map`.

## Swapping the Monitored Application

The system is application-agnostic. To monitor a different application:

1. Update `projects.yaml` — add a new entry with `observability_mode: datadog`
2. Rebuild and push the ingestion-agent image (projects.yaml is baked in)
3. Force a new ECS deployment for `ingestion-agent`
4. Seed the new service in `service_repo_map`

No code changes required. Credentials stay in SSM Parameter Store.

## Cost Estimate (us-east-1, approximate)

### Within AWS Free Tier (first 12 months)

| Resource | Spec | Free tier | ~$/month |
|---|---|---|---|
| EC2 t3.micro (ECS host) | 1 instance | 750 hrs/month ✓ | **$0** |
| RDS db.t3.micro | 20 GB gp3, single-AZ | 750 hrs + 20 GB ✓ | **$0** |
| SSM Parameter Store | 6 SecureString params | Standard params ✓ | **$0** |
| ECR | 4 repos, ≤3 images each | 500 MB ✓ | **$0** |
| CloudWatch Logs | 7–14 day retention | 5 GB ingestion ✓ | **~$0–1** |
| NAT Gateway | none — public subnets only | — | **$0** |
| ALB | none — direct EC2 access | — | **$0** |
| **Total (free tier)** | | | **~$0–1/month** |

### After 12-month free tier expires

| Resource | ~$/month |
|---|---|
| EC2 t3.micro | ~$8.50 |
| RDS db.t3.micro | ~$15 |
| SSM Parameter Store | $0 (always free) |
| ECR + CloudWatch | ~$1–2 |

> **Tip:** Stop ECS services and the RDS instance when not demoing — RDS can be stopped for up to 7 days at a time, and stopped EC2/RDS instances don't count against free-tier hours.
>
> ```bash
> # Stop all services when not in use
> aws ecs update-service --cluster banking-app-cluster --service banking-app      --desired-count 0
> aws ecs update-service --cluster banking-app-cluster --service ingestion-agent  --desired-count 0
> aws ecs update-service --cluster banking-app-cluster --service rca-agent        --desired-count 0
> aws rds stop-db-instance --db-instance-identifier banking-app-rca-db
> ```

## Tearing Down

```bash
cd terraform/aws

# Stop ECS services first (avoids dependency issues during destroy)
aws ecs update-service --cluster banking-app-cluster --service banking-app      --desired-count 0
aws ecs update-service --cluster banking-app-cluster --service ingestion-agent  --desired-count 0
aws ecs update-service --cluster banking-app-cluster --service rca-agent        --desired-count 0

# Destroy all infrastructure
terraform destroy -var-file=terraform.tfvars
```

> **SSM parameters** are deleted immediately by `terraform destroy` — no recovery window.
> **ECR images** must be deleted manually before the repositories can be destroyed, or set `force_delete = true` in the ECR resource.
> ```bash
> # Quickly empty all four ECR repos before destroy
> for repo in banking-app banking-app/ingestion-agent banking-app/rca-agent banking-app/dd-agent; do
>   aws ecr list-images --repository-name "$repo" \
>     --query 'imageIds[*]' --output json \
>   | xargs -I{} aws ecr batch-delete-image --repository-name "$repo" --image-ids {}
> done
> ```

## CI/CD (Not Implemented)

The project does not have a CI/CD pipeline. To deploy a code change:

1. Build the updated image locally
2. Push to ECR with a new tag (or `latest`)
3. Run `aws ecs update-service ... --force-new-deployment`

For a production setup, a GitHub Actions workflow would automate steps 1-3 on push to `main`. This is tracked as a future improvement.
